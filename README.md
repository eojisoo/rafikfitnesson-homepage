# 라피끄 천호역점 상품 예약·결제

천호역점 페이지의 `experience-booking.html`에서 체험권·이벤트 상품을 고르고, 필요하면 수업 시간을 예약한 후 토스 결제 위젯으로 결제합니다. 서버가 주문 상품의 실제 금액을 확인하고 결제를 승인한 뒤 SQLite에 확정하며, 구글시트의 고정 행에 기록합니다. 네이버 예약 이동은 없습니다.

## 여러 상품과 가격 등록

`booking-config.json`의 `products` 배열에 판매 상품을 **한 가격당 한 항목**으로 넣습니다. 같은 프로그램의 체험권과 이벤트권도 서로 다른 `id`를 씁니다. `category`가 화면의 그룹 제목이고, `amount`가 실제 청구액(원, 부가세 포함 총액)입니다. `description`과 `terms`에는 이용 기간, 포함 사항, 대상, 취소·환불 조건 등 고객에게 보여줄 설명을 넣습니다. 이벤트는 선택적으로 `saleEndDate`를 `YYYY-MM-DD`로 설정할 수 있습니다. 기한이 지나면 주문을 받지 않습니다.

```json
{
  "id": "pilates-trial",
  "category": "체험권",
  "name": "필라테스 1회 체험",
  "description": "기구 수업 1회",
  "terms": "실제 운영 조건과 취소·환불 안내를 입력",
  "amount": 0,
  "enabled": false,
  "requiresSlot": true,
  "resourceId": "pilates-class",
  "weeklySlots": {"1": [{"time": "19:00", "capacity": 7}]}
}
```

위 코드는 구조 예시입니다. 실제 상품 금액은 아래 판매 전 목록에 입력되어 있습니다. 운영 조건을 완성한 뒤 해당 항목을 `enabled: true`로 바꿉니다. `requiresSlot: false`인 헬스 이용권 같은 상품은 수업 시간 선택을 생략합니다. 동일한 수업을 다른 가격으로 판매하면 같은 `resourceId`, `weeklySlots`, 정원을 설정하세요. 두 상품의 판매량이 같은 잔여석에서 차감됩니다. 요일은 `0=일요일`부터 `6=토요일`입니다. 휴강일은 최상위 `closedDates`에 적습니다. 현재 파일에는 요가·필라테스·바레 체험권 각 22,000원, 헬스 일일 이용권 22,000원, 헬스 3개월 이벤트 108,900원이 입력되어 있습니다. 모두 `enabled: false`로 잠겨 있으므로 결제되지 않습니다. 요가·필라테스·바레의 수업 시간표와 상품별 이용·환불 조건을 채운 뒤 판매를 켜세요.

## 실제 결제 오픈

Node.js 24 이상과 HTTPS로 접속할 수 있는 서버가 필요합니다. 정적 HTML 호스팅만으로는 시크릿 키 보관, 주문 저장, 토스 결제 승인, 구글시트 기록을 실행할 수 없습니다. 단일 서버의 `data/` 폴더를 영구 디스크로 운영하세요. 현재 SQLite 구성은 서버 여러 대에 나누어 배포하는 용도가 아닙니다.

1. 토스페이먼츠에 **온라인 결제** 계약 상태를 확인하고 주문서형 결제용 테스트 클라이언트 키와 짝이 되는 시크릿 키를 받습니다. 매장 단말기 계약만으로 온라인 사용이 가능한지는 계약 상태를 확인해야 합니다.
2. `.env.example`을 `.env`로 복사해 테스트 키를 입력합니다. 구글 서비스 계정을 만들고 예약을 기록할 시트를 그 계정 이메일에 편집자로 공유합니다. `GOOGLE_SHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`를 서버 환경변수에 넣습니다. `예약` 탭 A1:J1은 `주문번호,지점,상품,예약일,시간,이름,전화번호,결제금액,결제일시,상태`로 시작합니다.
3. 실제 상품 금액·조건·시간표, `privacyPolicyUrl`, 사업자 및 환불 안내를 사이트에 반영합니다. `npm start`로 테스트 결제와 취소·마감·구글시트 기록을 확인합니다. 테스트 키에서는 실제 청구되지 않습니다.
4. 카드사 심사와 온라인 결제 계약이 완료되면 라이브 클라이언트/시크릿 키를 **서버 환경변수**로 바꾼 다음 실제 결제와 시트 기록을 다시 검증합니다. 키를 HTML이나 공개 저장소에 넣지 마세요.

서버와 `public/`을 같은 HTTPS 도메인에서 서비스하세요. `public/cheonho.html`은 기존 사이트의 `style.css`와 `images/`를 참조하므로 해당 파일도 함께 배포합니다.

결제 후 시트 기록이 일시적으로 실패해도 DB에는 결제 완료가 남습니다. `POST /api/admin/sync-sheet`에 `Authorization: Bearer <ADMIN_SYNC_TOKEN>`을 보내 누락 건을 다시 기록할 수 있습니다. `confirming` 상태에서 결제 응답이 불확실한 건은 토스 관리자 결제 내역과 대조하세요. 고객에게 재결제를 안내하기 전에 확인해야 합니다.
